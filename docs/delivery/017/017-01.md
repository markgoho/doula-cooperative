## Hugo Best Practices: Directory & File Organization (2024)

### Standard Hugo Directory Structure

According to the [official Hugo documentation](https://gohugo.io/getting-started/directory-structure/), a typical Hugo project includes:

- `archetypes/` — Content blueprints (e.g., `default.md`)
- `assets/` — Asset pipeline files (SCSS, JS, images for processing)
- `content/` — Site content (Markdown, page bundles)
- `data/` — Data files (YAML, TOML, JSON, XML)
- `i18n/` — Translation tables for multilingual sites
- `layouts/` — Templates and partials
- `static/` — Static files copied directly to `public/` (e.g., favicon, robots.txt)
- `themes/` — Optional themes
- `hugo.toml` or `config/` — Site configuration
- `public/` — Build output (not versioned)
- `resources/` — Asset pipeline cache (not versioned)

### Best Practice Highlights

- **Use `content/` for all site content** (Markdown, bundles, images for posts)
- **Use `static/` for files that don’t need processing** (favicons, robots.txt, etc.)
- **Use `assets/` for files processed by Hugo Pipes** (SCSS, JS, images for optimization)
- **Organize SCSS/CSS modularly** (e.g., `assets/scss/` with partials, main entrypoint)
- **Keep `layouts/` organized**: `_default/` for base/list/single, `partials/` for reusable components
- **Do not version `public/` or `resources/`**
- **Consider splitting config into `config/_default/hugo.toml` for complex sites**
- **Add `data/` and `i18n/` if using data-driven or multilingual features**

### Comparison to Current Project Structure

**Present:**

- `archetypes/` (has `default.md`)
- `assets/scss/` (modern, modular SCSS)
- `layouts/_default/` and `layouts/partials/` (well-structured)
- `public/` and `resources/` (build/cache output)
- `hugo.toml` at root
- **Missing:** `content/`, `static/`, `data/`, `i18n/`, `themes/` (if needed)

**Notes:**

- The absence of a `content/` directory means no site content will render; this is essential for a working Hugo site.
- No `static/` directory: add for unprocessed assets (favicons, robots.txt, etc.).
- `data/` and `i18n/` are optional, but recommended if you plan to use data files or multilingual features.
- `themes/` is only needed if using or developing a theme.

### Recommendations

1. **Add a `content/` directory**
   - Place all Markdown content and page bundles here.
   - Example: `content/posts/first-post.md`, `content/about/index.md`
2. **Add a `static/` directory**
   - For files to be copied directly to `public/` (e.g., favicon, robots.txt, manifest.json).
3. **Add `data/` and `i18n/` directories if needed**
   - `data/` for YAML/TOML/JSON files to power menus, configs, etc.
   - `i18n/` for translation files if supporting multiple languages.
4. **Consider moving config to `config/_default/hugo.toml`** if you expect to support multiple environments or want to follow the latest Hugo convention (optional for simple sites).
5. **Continue using `assets/scss/` for SCSS** — this is modern and recommended.
6. **Do not version `public/` or `resources/`** — these are build outputs.
7. **Document this structure in your project README** for onboarding and consistency.
